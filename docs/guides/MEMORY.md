# 记忆与性格：她为什么会变

> 这套东西有**两层**：短期记忆管「刚才聊到哪」，长期记忆管「半年后还记不记得」，
> 自我认知（`selfBelief`）管「我变成了什么样」。
> 前两层影响她说得对不对，第三层影响她**是谁**。

本文对应代码：`src/bridge.js`（后端）+ `src/mcp-snowluma-safe.js`（工具面）+ `state/`（数据）。

---

## 一句话总览

```text
每条消息 ──落盘──▶ state/longterm/raw/<日期>.jsonl        （原始存档，永不丢）
                     │
        攒够 10 条 ──┴─▶ 提炼器（独立会话，调模型）
                          │
                          ▼
        ┌─────────────────┴──────────────────┐
        │ 短期五类（social-v2.json）          │ 长期四类（longterm/）
        │  activeTopic    在聊什么            │  episode   发生了什么
        │  pendingThought 想说还没说          │  fact-yg   关于他
        │  memberImpression 对谁什么印象      │  fact-us   关于我们
        │  selfBelief     我变成什么样了 ←性格 │  fact-self 我自己的变化
        │  contentMemory  刷到什么好东西      │
        └────────────────────────────────────┘
                          │
                  下次唤醒时注入 prompt
```

## 第一层：短期记忆（五类）

存在 `state/social-v2.json` 的每个会话下，有过期与容量上限，**故意会忘**。

| 类别 | 记什么 | 生命周期 | 容量 |
| --- | --- | --- | --- |
| `activeTopic` | 正在聊的话题、参与者、还没问出口的问题 | 24 小时没再提起就清掉 | 20 条 |
| `pendingThought` | 想说但还没说出口的话 | 默认 2 小时过期（可传 `expiresAtMs`） | 20 条 |
| `memberImpression` | 对某位群友的印象标签、互动次数 | 长期累计 | 每个成员最多 10 个标签 |
| `selfBelief` | **「我变成什么样了」—— 性格变化的载体** | 见下一节 | 24 条 |
| `contentMemory` | 刷到的、真的让她停下来的内容 | 长期 | 40 条 |

工具：`qq_memory_append` 写、`qq_memory_query` 读。两者都只作用于当前会话。

### 为什么短期记忆也要有「过期」

因为人格的注意力是有限的。`pendingThought` 如果不过期，三个月前一句没说的话
会一直挂在 prompt 里，占位置、还让她莫名其妙。`activeTopic` 同理 ——
一个已经聊完的话题还在，只会让她反复往回拉。

**过期不是 bug，是设计。** 真重要的东西走长期记忆那一层。

## 第二层：长期记忆（事件 + 事实）

存在 `state/longterm/`，**Markdown 是真相源，`index.json` 只是可重建的缓存**。

```text
longterm/
  index.json              索引（L0 摘要行；坏了删掉能重建）
  episodes/2026-11-01.md   那天发生了什么（正文）
  facts/about-yg.md        关于他的事实
  facts/about-us.md        关于你们的约定、纪念、争执与和好
  facts/about-self.md      关于她自己的变化
  raw/2026-11-01.jsonl     原始消息存档（每一条，先落盘再处理）
```

### 为什么要有 Markdown 这一层

两个理由，都很实际：

1. **她能被用记事本打开看。** 记忆不是黑盒里的一个向量库，是一个你能直接读、
   直接改、直接删的文件。
2. **索引可以坏，知识不能丢。** `index.json` 解析失败就当空的重建 ——
   正文都还在 Markdown 里。

### 分层读取：为什么首条消息只载入十几条

参考 tigerless-labs/agent-memory 的分层思路（只借思路，没装它们的东西）：

```text
L0 索引行（abstract 一句话 + id）  ← 每次唤醒注入，约 16 条
   ↓ qq_memory_search("关键词")
若干条摘要
   ↓ qq_memory_read(id)
全文 body
```

prompt 里只给 L0。要看细节她自己搜、自己展开 —— 这是「96.9 万字只载入 7.2K」
那套做法。默认 16 条可以用 `socialV2.longTerm.promptLimit` 调（6–30）。

### 挑哪几条注入：权重 × 新鲜度

```text
score = weight × 100 + max(0, 14 − 已存在天数) × 6      （已被取代的直接排除）
```

含义：重要的事（约定、雷点、人生转折）永远在；日常琐事会自然下沉 ——
不是被删掉，只是排不进前 16 条。`supersedes` 让新条目取代旧条目，
旧的不删、只是不再参与召回。

### 自动提炼

- 每个会话维护一个消息缓冲，**攒够 10 条**触发一次提炼
  （原来 20 条，实测一天下来记不了几条，改小了）。
- 提炼器是一个**独立会话**（复用黑话学习器那个，不参与聊天回复），
  串行队列，一次一个。
- 提炼前**先把原始消息落盘**：被提炼器漏掉 ≠ 被系统丢掉。
- 提炼 prompt 里专门教模型分清三个说话人：「我」= 她自己、
  「神眷之樱花」等 = 他、群里的其他人 = 群友。搞混人称是这类系统最常见的坏味道
  （「小鱼儿最爱辣椒炒肉」—— 而小鱼儿根本不是她）。
- 一次 10–30 条消息，正常能提炼 3–8 条。只出 1 条说明漏了。

手动记重要的事用 `qq_memory_record`（4 类 + weight 1–10 + 可选 `supersedes`）。

## 第三层：性格为什么会变（`selfBelief`）

这是整套系统里**唯一会改「她是谁」**的部分。角色卡（`roles/*.md`）是写死的，
`selfBelief` 是长出来的。

### 数据结构

```js
{
  text: '我好像不那么怕被怼了',
  since: 1730000000000,        // 什么时候开始这么想
  until: null,                 // 什么时候「已经过去了」（非空 = 已结束）
  changedBy: '他怼我的时候我没躲',  // 因为什么改的
  weight: 2,                   // 1–5，注入力度
  lastReinforcedAt: 1730000000000,
}
```

### 三个让它「活起来」的机制

**1. 重复是强化，不是重复。**
同一条再写一次 → `weight + 1`（上限 5）。想法越确认，注入时措辞越肯定。

**2. 措辞按 weight 分层 —— 不确定的就说「好像」。**

```text
weight ≥ 4   → 直接说
weight 2–3   → 「大概我…」
weight 1     → 「好像我…」
```

但如果原文本身就以「好像/大概/可能」开头，就不再加前缀 ——
否则会长出「大概我好像…」这种明显是机器写的句子。

**3. `until` 让旧想法「结束」而不是「消失」。**

```text
【我变成什么样了】
- 我不那么怕被怼了（因为他怼我的时候我没躲）

【我以前是这样，但现在不是了】
- 以前：我怕被怼 —— 那次他说了那句话
（这些是你自己想通的，不是谁命令你改的。记得那种变化。）
```

旧想法留着，但变成「以前」。这条比直接删掉重要得多 ——
知道自己**曾经是谁**，才谈得上「变」。

### 容量：24 条，淘汰有优先级

满了先挤掉「已结束 + weight 最低 + 最老」的。所以留下的是：还有效的、强度高的。

### 每晚自省（`selfReflect`）

- 时间：**23:00 ~ 01:00 之间随机**。真人不会准点自省。
- 当天说过话才自省（没说话就没东西可选）。
- 那一轮的 prompt 明确写着：「**这不是聊天，不用发消息**」——
  看的是「今天有没有哪一刻，你的反应和以前不一样」。
- 硬规则：**今天没什么想通的，就什么都别记。** 硬编一条出来比不记更糟。

这一轮是她性格变化的**主要来源**：白天积累，晚上自己回看，然后决定要不要改对自己的看法。

## 一个真实踩过的坑（值得单独记）

记忆系统在 `bridge.js` 里写得很完整，但 **MCP 工具那一层的 zod schema 没声明
`selfBelief` / `contentMemory` 需要的字段**，而 zod 默认会丢掉未声明的键。

后果，从外面完全看不出来（工具都返回成功）：

| 症状 | 原因 |
| --- | --- |
| 性格永远不变 | `changedBy` / `until` / `weight` 被丢掉，每条自我认知都是「没有来由的一句话」 |
| 刷到的东西一条都不记 | `platform` 被丢掉 → 后端 `if (!platform) return` |
| `pendingThought` 的过期时间调不动 | `expiresAtMs` 靠默认值 |

修法是把这些键补进 schema（`src/mcp-snowluma-safe.js` 里 `qq_memory_append`），
并用 `scripts/test-memory-contract.mjs` 钉住：**它解析一遍参数，断言解析之后这些键还在**。
撤掉修复这条用例会红 4 条 —— 已经实测过。

> 一般教训：**「后端读了哪些字段」和「工具面允许传哪些字段」是两份清单，
> 它们会静默错开。** zod 的默认行为是丢掉，不是报错，所以这种错开不会在日志里留下任何痕迹。

## 配置项

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `socialV2.tools.memory` | `true` | 记忆工具的开关（关掉后 `qq_memory_*` 不注册） |
| `socialV2.longTerm.promptLimit` | `16` | 每次注入多少条 L0 摘要（夹在 6–30） |

其余容量/过期是代码里的常量，改动前先看 `LTM_DISTILL_MIN`（10）、
`LTM_BUFFER_MAX`（200）、`selfBeliefs` 上限 24、`contentMemories` 上限 40 这几处。

$S = 'state\longterm'
type $S\facts\about-self.md      # 她对自己的看法（性格变化）

（`index.json` 不是真相源，删了不丢知识 —— 这是当初就这么设计的。）
